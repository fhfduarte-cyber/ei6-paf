# Ei6 · PAF tool (Vercel + PHP + Supabase)

Web version of the raw-material / PAF calculator.

```
Browser ──HTTPS──> Vercel (PHP 8.3, vercel-php@0.7.3)
                      │  templates/app.html  (calculator UI, datasets injected as JSON)
                      │  api/index.php → src/*  (auth, PAF API, admin API)
                      └──> Supabase: Auth + Postgres (RLS) — PAFs, datasets (prices, Parma stock, Devaluation rules)
```

* **PAFs** are saved in Postgres (version-controlled, with history and audit). The old `.json` file remains as *Export/Import file* (backup).
* **Reference data** (price lists, Parma Aged Report snapshot, Devaluation v7 rules) lives in the `datasets` table; admins update it without redeploying.
* **Excel PAF form** is still generated in the browser (ExcelJS), from the data the user is allowed to see.

## 1. Supabase
1. Create a project (choose a region close to your Vercel region).
2. SQL editor → run, in order: `supabase/migrations/0001_init.sql`, then `0002_seed_datasets.sql`.
3. Authentication → Providers → Email: disable *Allow new users to sign up* (see `SECURITY.md`).
4. Authentication → Users → *Invite user* (or Add user). Then in the SQL editor:
   `select public.grant_access('first.user@ei6.com', 'admin');` (use `'member'` for others).
5. Project Settings → API: copy the **Project URL** and the **anon (publishable) key**. (Optional: the legacy JWT secret.)

## 2. Vercel
1. Push this folder to a Git repository and import it in Vercel (Framework preset: *Other*). No build command.
2. Environment variables (Production + Preview): `SUPABASE_URL`, `SUPABASE_ANON_KEY`, optional `SUPABASE_JWT_SECRET` (see `.env.example`).
3. Deploy. Open the URL, sign in, create a PAF.

`vercel.json` pins the community PHP runtime (`vercel-php@0.7.3` → PHP 8.3). Vercel does not officially support PHP: if the runtime is
ever discontinued, the `src/` classes run unchanged on any PHP 8.3 host (Railway, Fly, a VPS) behind `api/index.php`.

## 3. Updating reference data
* Admin API: `GET/PUT /api/admin/datasets/{prices_blocks|prices_rods|prices_rounds|devaluation|parma_stock}` (admin only, same-origin, JSON `{"data": ...}`).
* Or edit the `datasets` table in the Supabase dashboard. Formats are in `supabase/seed/*.json` (generated by `tools/extract_datasets.mjs` from the legacy workbook snapshot).
* New Parma Aged Report ⇒ regenerate `parma_stock` (`rows` = the array used by the Material Digger) and PUT it.

## 4. Local development & tests (no Supabase needed)
```bash
./tests/run_servers.sh            # mock Supabase :54321 + PHP :8081  (APP_ENV=local)
python3 tests/api_test.py         # 40 API/security checks
python3 tests/e2e.py              # browser end-to-end under the real CSP (needs playwright + exceljs in /tmp/xl)
psql -f tests/rls.sql             # RLS/trigger checks on a scratch Postgres (needs a stub of Supabase's auth schema, see header of the file)
```
Against a real project use `APP_ENV=local php -S 127.0.0.1:8081 api/index.php` with the env vars set.

## Layout
```
api/index.php            single entry point (vercel.json routes every path here)
src/                     Config, Http (headers/CSP/CSRF), Jwt, Supabase client, Session, PafValidator, Pafs, App, Router
templates/app.html       calculator UI (generated from the legacy single file by tools/make_template.py, then edited)
templates/login.html
supabase/migrations/     schema + RLS + triggers; seed of datasets
tools/                   extraction/conversion scripts
tests/                   mock Supabase + API and E2E tests
```
